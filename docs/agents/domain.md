# Domain Docs

This is a single-context repository. When domain decisions need durable documentation,
keep `CONTEXT.md` at the repository root and architecture decision records in
`docs/adr/`.

Before domain exploration, read `CONTEXT.md` and relevant records in `docs/adr/` when
they exist. If they are absent, proceed without treating that as a review finding;
create them when the project reaches decisions worth recording. Use established
project terms and surface conflicts with existing decision records.
